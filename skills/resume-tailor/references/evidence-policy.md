# Evidence Policy

## Source priority

Use sources in this order:

1. Uploaded current résumé for current facts and structure.
2. Optional approved Bullet Library for previously accepted wording only; revalidate every claim against current authoritative evidence.
3. Evidence explicitly marked `verified` by the user or an authoritative source file.
4. Facts the user explicitly confirms for this application.
5. Everything else is `unverified` and unusable.

When sources conflict, keep the more conservative claim and flag the conflict. Do not silently rewrite the source résumé or long-term evidence file.

## Protected claim dimensions

Preserve:

- ownership: `led`, `owned`, `contributed`, `supported`, or team-owned;
- delivery state: research, proposal, prototype, pilot, launched, or scaled;
- scope: users, markets, workflows, systems, and duration;
- metrics: value, unit, denominator, direction, and time window;
- causality: measured impact versus correlation or team result;
- technical depth: used, configured, evaluated, integrated, built, or trained.

Never invent or upgrade title, ownership, scope, metric, causality, technical implementation, customer audience, or launch state.

## Supplemental evidence

Use supplemental evidence only when it is specific enough to defend in an interview and can fit a real résumé slot. A keyword change does not turn missing evidence into a match.

If the user remembers a new fact during tailoring, label it `user-confirmed` in the run. Ask one follow-up only if a missing ownership, artifact, audience, or outcome detail changes Core coverage. Otherwise use conservative wording.

Planned learning, future portfolios, and unfinished projects may become a learning suggestion but never résumé evidence.

## Approved Bullet Library

The library is optional and must not block a first run. Store only final, approved, materially distinct résumé-grade bullets. Group entries by experience/project and tailoring focus. Do not store light synonym, punctuation, or keyword-only variants. A library entry is an expression candidate, not independent proof.
