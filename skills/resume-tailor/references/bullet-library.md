# Approved Bullet Library

Use this file as wording memory, not evidence. It is optional: a first-time user can start with only a résumé and complete JD.

## Format

Group approved wording by Experience and Project, then keep only two fields:

```markdown
## Experience: <company or organization>

### Project: <project or workstream>

| Tailor Focus | Approved Bullet |
|---|---|
| <JD capability or recruiter-recognizable focus> | <final human-approved résumé bullet> |
```

## Search before drafting

1. Search the Bullet Library before drafting by Experience, Project, and Tailor Focus.
2. Revalidate every candidate against the uploaded résumé or verified evidence. A library row never proves a fact.
3. Reuse a row only when its ownership, scope, delivery state, metric, causality, and technical depth still match.
4. If no suitable row exists, draft from verified evidence using `bullet-policy.md`.

## Save adopted bullets

After human feedback is resolved and PDF plus ATS/layout QA pass, save adopted bullets only when they are final, human-approved, résumé-grade, and materially distinct from existing rows.

Do not save keyword-only, punctuation, grammar, article-removal, bolding, or light-synonym variants. Add or update only the matching Experience and Project table; never delete or rewrite unrelated entries.
