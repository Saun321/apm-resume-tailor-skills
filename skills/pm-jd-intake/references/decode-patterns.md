# JD Decode Patterns

Use these as priors, not automatic conclusions. The complete JD context always wins.

## Marketing language to real screening bar

| JD wording | Likely practical meaning |
|---|---|
| strong experience with X | Has done X and can explain decisions and outcomes |
| deep expertise in X | X is probably a true screening axis |
| working knowledge / exposure | Usually adjacent or Nice-to-have |
| shipped X | Needs concrete launched work or a defensible artifact |
| data-driven | Must connect analysis to a product decision |
| 0-to-1 / ambiguity / no playbook | Must define the problem, not only execute requirements |
| scale / 1-to-N | Needs growth, reliability, operations, or platform judgment |
| collaborate / influence / align | Cross-functional persuasion is part of the job |
| hands-on technical | Must perform or closely direct technical work, not only coordinate |
| customer-obsessed | Needs discovery evidence and customer-linked decisions |

## Core Must-have test

Upgrade a deduplicated Must-have to `Core` only when it is repeated, prominent, tied directly to the main outcome, or essential to day-one performance. Repetition alone is not enough. Keep Nice-to-haves separate.

After decoding, ask whether the requirements support three recruiter questions:

1. Has this person solved the central problem?
2. Can this person operate at the required ownership and technical depth?
3. Does the résumé show the working style and outcomes this team rewards?

## Hidden Signals

| Signal wording | Inference to test against résumé evidence |
|---|---|
| ambiguity / self-directed | Defines problems and next steps independently |
| ownership / accountable / drive | Carries decisions through delivery and learning |
| partner / influence / align | Handles high collaboration and persuasion cost |
| fast-paced / scrappy / ship | Makes good trade-offs under time pressure |
| high bar / craft / quality | Uses explicit quality standards and iteration |
| experiments / metrics | Owns hypotheses, measurement, and decision narrative |
| first PM / founding / build the function | Role may carry hidden senior scope |
| execute against roadmap / mentorship | More junior-friendly scope |

Score only the 3–5 signals most likely to affect hiring. Do not use generic communication or passion language unless the JD clearly screens for it.

## True gates versus priority factors

Treat explicit work authorization, required licensure, clearance, physical presence, language fluency, or incompatible senior scope as possible gates. Verify exact wording before applying `KILL`.

Keep relocation preference, compensation, company interest, commute, and application cost in Opportunity Priority, not Match. Treat industry mismatch as a score factor only when industry knowledge is a real requirement or necessary for immediate performance.

## Product and team context

If current information is needed, research only enough to identify product line, product stage, users/business model, the PM responsibility area, and a meaningful reason the company may be hiring now. Prefer official sources. Label unsupported conclusions as inference and never use company research as candidate evidence.
